# 非侵入式负荷监测（NILM）工厂端 AI Agent 业务与产品需求规格说明书

## 1. 文档概述与项目背景

### 1.1 业务背景
在现代工业制造企业中，配电能耗成本占据企业运营支出的显著比例。设备制造型工厂、铸造、注塑、精密加工等高能耗企业普遍面临以下痛点：
- **能耗粗放**：只知每月总电费金额，不知各个生产车间、独立产线及单台高功率设备（如空压机、注塑机、工业电炉、大功率空调）的具体用电明细；
- **隐患盲区**：过载跳闸、三相负荷不平衡、高次谐波畸变、违规大功率电器使用等电气安全隐患难以及时预警，常在引发火灾或停机事故后才被发现；
- **罚款损失**：由于功率因数（$\cos\varphi$）低于供电局考核基准（通常为 0.90），每月被加收高额“力调电费”惩罚，缺乏及时的无功补偿调整指导；
- **运维门槛高**：工厂配电电工与能源主管缺乏专业的数据统计工具，面对繁复的电流、电压时序曲线无从下手。

### 1.2 核心技术底座：非侵入式负荷监测（NILM）
我司自主研发并生产的**非侵入式负荷监测设备（NILM, Non-Intrusive Load Monitoring）**打破了“每台设备都必须安装物理电表与传感器”的传统高成本模式。
- **技术原理**：只需在变压器低压出线端或车间总配电箱处安装 NILM 监测装置，通过秒级采集母线的电压、电流与稳态电气特征（包含有效值、有功/无功功率、功率因数及各次谐波等），结合特征提取与负荷分解算法，即可精准识别出下属各个受电设备的开关状态、启停时刻、瞬时功率与能耗变化。
- **采集指标**：包含三相有效电压（U）、有效电流（I）、有功功率（P）、无功功率（Q）、视在功率（S）、功率因数（PF）、电网频率（Freq）、2~7 次谐波电流含有率，以及细分设备启停特征状态。
- **工厂-车间-多终端多层级拓扑模型**：
  在实际工业部署中，工厂资产呈现严格的五级物理与逻辑拓扑：
  ```text
  企业/工厂 (Tenant)
    └── 车间/厂房/楼宇 (Workshop / Building, 一厂可含多车间)
          └── 配电柜/NILM终端 (Terminal, 一车间可装多台终端监测不同配电支路)
                └── 采集通道 (Channel, 单台终端支持多个三相/单相通道)
                      └── 细分负荷设备 (Appliance, NILM 算法分解出的具体受电设备)
  ```
  这一层级关系要求 AI Agent 必须具备**跨设备聚合求和**与**自顶向下逐层下钻**能力。

### 1.3 建设目标
借助开源 **DeepSeek Harness (dsh)** 框架，构建面向工厂客户的后台 AI Agent 智能服务程序。客户通过微信小程序或移动端 App，使用**文字或语音**提出业务诉求，Agent 自动解析意图、调用底层关系型数据库（MySQL）与时序数据库（TDengine）进行精准计算与因果分析，以通俗专业的多模态形式（文字说明 + 交互式图表卡片）实时反馈结果。

## 3. 功能性需求（Functional Requirements）

### 3.1 FR-1：用电能耗监测与电费核算
- **FR-1.1 灵活时间区间查询**：支持用户以自然语言指定查询时间（如“昨天”、“本周”、“上个月”、“2024年10月1日到10月7日”）。
- **FR-1.2 空间层级下钻与多终端智能聚合**：
  - **全厂级聚合**：用户询问“全厂总用电”时，Agent 自动遍历该企业下属所有车间、所有安装的 NILM 终端与通道并计算总和；
  - **车间级多终端聚合**：一个车间或厂房常装有多台监测终端分别监测不同变压器段或母线槽。当用户询问“二号车间总用电”时，Agent 自动联动检索该车间绑定的所有终端列表，并将所有终端/通道电量求和，避免遗漏分路；
  - **终端与通道下钻**：支持精确查询某特定配电柜、某台终端、某通道回路的独立用电负荷；
  - **设备级溯源**：支持查询特定细分设备究竟挂在哪个车间的哪台终端下运行。
- **FR-1.3 峰平谷分时电量统计**：结合不同工厂所在地的峰平谷分时电价时段，计算尖峰、高峰、平时、低谷的用电度数（kWh）与预估电费。
- **FR-1.4 环比与同比趋势**：支持日环比、周环比、月同比等能耗走势对比，自动生成对比结论与趋势走向。

### 3.2 FR-2：NILM 设备级负荷特征分解
- **FR-2.1 设备工况辨识**：基于 NILM 负荷识别算法（关联 `nilmdc_appliance_identification`），解析特定品类设备（空压机、注塑机、电加热器、空调等）的开机、关机及工况切换时刻。
- **FR-2.2 开机与空载时长统计**：计算指定统计期内的累计运行小时数、待机空载时长。
- **FR-2.3 异常工况能耗浪费评估**：当非生产班次（如深夜 00:00~06:00 或节假日）检测到设备持续运行且处于低负荷空载态时，自动核算空载浪费电量并发出节能提示。

### 3.3 FR-3：电气安全隐患排查与预警
- **FR-3.1 隐患事件多维检索**：支持检索指定时段内的电气安全事件（单设备过载 `overload_single_power`、三相不平衡、过欠压、异常冲击负荷）。
- **FR-3.2 隐患细节展开**：提供隐患发生时间、发生点位（支路名称）、瞬时功率（kW）、瞬时电流（A）以及违规设备名称。
- **FR-3.3 故障成因辅助诊断**：结合电力专业规则，对过载原因（如多台重载设备同时启机引发浪涌）给出排查指引。

### 3.4 FR-4：电能质量分析与能效体检
- **FR-4.1 功率因数评估与罚款预警**：统计月度与日度平均功率因数（$\cos\varphi$）。当数值低于标准值（0.90）时，触发严重预警，并告知可能引发的供电局力率调整罚款风险；
- **FR-4.2 高次谐波畸变监测**：分析 2、3、5、7 次谐波电流畸变率，排查非线性用电负荷（变频器、中频炉、整流电源）对厂区供电回路造成的污染；
- **FR-4.3 能效改善方案建议**：给出改善无功补偿电容投入、削峰填谷生产排班的专业工程化建议。

### 3.5 FR-5：主动巡检与定时通知推送
- **FR-5.1 每日能耗晨报**：基于 Harness `Schedule` 定时调度机制，每天早晨 08:30 自动生成前一日工厂用能简报（昨日总电量、环比变化、重点设备开机关机情况）。
- **FR-5.2 夜间异常用电自动告警**：在非工作时间巡检全厂基载功率，若突发异常负荷跃升或违规用电，自动触发预警。

## 4. 交互形态与输入输出规范

### 4.1 终端接入形式
- **微信小程序端**：工厂管理员最常用的移动端载体，免安装、支持微信扫码直接绑定企业身份；
- **移动端 App**：针对厂区值班室 iPad 或中控大屏的增强客户端。

### 4.2 输入模态支持
- **文本输入**：标准自然语言文本提问；
- **语音输入**：支持长按录音。前端集成“微信同声传译”SDK，松手即完成 ASR 语音转文字，并自动回填输入框触发提问。

### 4.3 输出展现形式
Agent 输出严格执行**流式交互 + 图文混排**：
1. **流式文字（Markdown）**：通过 Server-Sent Events (SSE) 或 WebSocket 实现打字机渐进式输出，包含核心结论、分析明细与建议；
2. **交互式图表卡片（ECharts Spec）**：当涉及趋势、占比或波形时，Tool 返回结构化图表 JSON，前端微信小程序自动渲染为折线图、柱状图或饼图；
3. **告警预警卡片**：使用红色/橙色高亮卡片标注严重安全隐患，包含一键通知电工或确认处理按钮。

## 5. 数据源与环境依赖要求

### 5.1 业务元数据（MySQL: `tpim_system`）
- **承载内容**：企业租户信息、微信用户绑定与权限、厂区/楼宇/车间物理空间树、NILM 主机与采集通道资产档案、安全隐患历史记录、电器品类特征字典。
- **连接通道**：
  - K8s 内部署：`mysql.mysql.svc.cluster.local:6446`
  - 外部访问：`121.41.8.7:30446`

### 5.2 热时序数据库（TDengine 3.0: `tpim_system`）
- **承载内容**：最近 90 天内的高频秒级/分钟级测量点位（电压、电流、有功/无功功率、功率因数、谐波、NILM 分解设备状态、小时/天预聚合能耗统计）。
- **连接通道**：`121.41.8.7`，支持 REST API 与 `taosws` WebSocket 驱动。

### 5.3 历史冷数据与消息管道（Kafka & 内网服务器: 192.168.1.67）
- **数据流向**：由于云端存储成本限制仅保留 3 个月热时序，全量原始数据通过 Kafka（9092 端口）持续同步到公司内网服务器进行长期冷存。
- **跨期查询策略**：超过 3 个月的同比/环比查询优先读取日度预聚合超表；秒级波形调取走内网安全代理通道。

## 6. 非功能性需求（Non-Functional Requirements）

### 6.1 安全与多租户强隔离
- **严格租户边界**：每个微信用户必须严格绑定唯一的 `tenant_id`。所有大模型工具调用与底层 SQL 查询必须强制附加 `WHERE tenant_id = ?`，严防 A 工厂用户刺探 B 工厂的生产能耗。
- **凭证零泄露**：生产环境绝对禁止硬编码数据库账号密码，统一由环境变量及安全密钥注入；MySQL 连接用户必须剥离 DDL/DROP 等高危权限，仅赋予只读权限。

### 6.2 严防大模型幻觉（Fact Grounding）
- 工业能耗涉及真金白银的电费核算与供配电安全。系统 Prompt 与 Tool 约束必须遵循“**数据未查出则据实说明，严禁胡编乱造**”原则。所有的电度数、功率峰值、电费估算必须由后端工具精确计算并输出，大模型仅负责专业解读与成因归纳。

### 6.3 响应性能要求
- **首字响应延迟（TTFT）**：首字流式输出时间控制在 1.5 秒以内（基于 DeepSeek-V3 快速推理通道）；
- **时序聚合响应时延**：近 90 天内的天级/月级能耗聚合查询控制在 300 毫秒以内；
- **并发能力**：支持百家工厂同时在线巡检查询，数据库连接池具备断线自动重试与弹性保活。

## 7. 术语表（Glossary）

| 术语 / 缩略语 | 全称 | 说明 |
| :--- | :--- | :--- |
| **NILM** | Non-Intrusive Load Monitoring | 非侵入式负荷监测。通过总线电气特征分解内部设备负荷的技术。 |
| **dsh** | DeepSeek Harness | 基于 Cordis 微内核的全插件化 Agent 编排框架。 |
| **STable** | Super Table | TDengine 时序数据库中的“超表”，是同一类时序采集设备的数据建模模板。 |
| **力调电费** | Power Factor Adjustment Charge | 供电局根据工业用户实际功率因数高低，对总电费实施奖励或惩罚性加收的电费政策。 |
| **功率因数 ($\cos\varphi$)** | Power Factor | 有功功率与视在功率的比值，表征电网电能的有效利用程度（标准通常为 0.90）。 |
| **THD** | Total Harmonic Distortion | 总谐波畸变率，衡量电网电能质量与谐波污染程度的核心指标。 |
| **BFF** | Backend For Frontend | 服务于前端小程序的业务接入网关层。 |
| **ASR** | Automatic Speech Recognition | 自动语音识别，将用户语音录音转换为文本。 |
